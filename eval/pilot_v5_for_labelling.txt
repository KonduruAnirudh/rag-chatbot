LABELLING STANDARD (the rules you applied to v4 - confirm or amend, then we hold it fixed):
  An edge is WRONG if any of these holds:
  1. The verb doesn't match its definition below.
  2. The direction is reversed.
  3. The quote doesn't STATE the relation - a purpose, benefit or effect is inferred
     (e.g. 'a playbook ... is provided as an example' does not state 'mitigates').
  4. An endpoint isn't the real participant in the quote: a substitute (the service
     instead of its customers) or the wrong actor (a process instead of the service doing it).

Changes in v5:
  - New verbs:
      creates    object is made deliberately by subject, or subject is the tool, console or API
                 used to make it (e.g. a web form used to open a ticket)
      evaluates  subject assesses, reviews or examines object (e.g. an auditor reviews logs)
  - Narrowed: produces = subject automatically generates or emits object as its own output
  - Prompt: if an endpoint would be something you must not extract (e.g. 'customers'), skip the
    relationship - never substitute a nearby named entity.
  - Code check: rejects an edge whose endpoint appears in the quote only as the modifier of a
    generic noun ('Shield Advanced customers').

Unchanged: protects (asset, never a threat), mitigates (a threat), contains (part of, or included
in a plan/package/product), related_to, and the rest. 'supports' does not exist.
